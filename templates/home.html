Calm architecture.

Small tools I run my hobby projects with. It started with questions, and each tool here is my answer to one.

The principle

You should be able to see what you made, all the way to where it runs.

Today, software disappears the moment it leaves your editor. It vanishes into layers: a CI language you can't run on your laptop, a container around a binary that didn't need one, a cloud console, dashboards behind logins. Each holds a fragment of the truth, and none of them knows about the others. So the simplest question an owner can ask, is what's running the code I wrote, and is it safe?, has nowhere to be answered. You assemble it by hand, or you stop asking.

Each tool here removes one of those layers, and together they give the sight back. That's what calm means here: not fewer alerts, but a quiet you can trust, because you could look.

Together

Tools that know about each other, and one terminal pane where they meet.

Each tool owns one stage, and works on its own: punchcard takes code to an audited binary, unit takes that binary to a running service, and smed builds the machines, configures them and keeps watch over them. None of them is a platform. But they leave records the others can read, and one fact runs through all of them: the checksum of the binary. So smed's watch can say what no single tool knows on its own.

punchcard builds every push and publishes each binary's checksum

unit deploys only that binary, byte for byte, and records its checksum on the server

punchcard audits the binaries it keeps for known vulnerabilities, again every night

smed watch asks every machine over Tailscale and joins it all by checksum

The source on main can be clean while a server runs last week's build. Because the checksum ties the audit to the exact binary that runs, smed's watch can say what no single tool can, and what to do about it:

✗ vt100   app vt100 reaches GO-2026-4441; a1b2c3d fixes it

  SECURITY from Punchcard
  audited 2h ago · govulncheck · bin/vt100 9463b1f
  ✗ GO-2026-4441  golang.org/x/net v0.17.0 → v0.45.0
  a1b2c3d fixes it: passed CI, audited without it → unit deploy

Deploy the fix and the line goes away by itself. When nothing needs you, the screen says Nothing needs you. and stays quiet. It also shows what each machine runs and uses, every deploy and package upgrade on one timeline, and a server that waits for a reboot, without logging in anywhere: Tailscale already knows who you are.
