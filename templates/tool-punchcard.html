What if mise run ci is the only pipeline you need?

{{.Principle}}

If a repo pins its tools and its build is one command, CI doesn't need a language of its own. It needs to run that command, on a machine that remembers. Punchcard is a one-binary CI server that does exactly that, and posts the result on GitHub.

Standing on hosted CI

Hosted CI made it normal that every push is built and tested before anyone trusts it, with the result right on the commit. It earns its complexity on a team: each job on a fresh, isolated machine, so strangers' pull requests and fifty developers can share one pipeline safely.

That isolation has a price. Every build starts from nothing: a fresh machine, fresh tool installs, cold caches. The pipeline is written in the CI's own YAML, which only runs there, so a failure is debugged by pushing again and waiting.

Punchcard makes the opposite trade. It is for a handful of repos and a machine you trust. It keeps a workspace per repo, resets it to the exact commit and runs the repo's own ci task. The toolchain is already installed and the caches are still there, so the build starts right away.

What you get from one command

Passes here, passes there

CI runs mise run ci, the command you run on your laptop. If it passes locally it passes in CI, and a red build can be reproduced on your own machine.

A machine that remembers

Each repo keeps its workspace. node_modules, build caches and toolchains survive between builds, and mise installs each tool version once.

Builds without commits

Install the GitHub App and every repo gets a first build. Set a nightly time and all of them are built again every night, so a repo that breaks on its own, from a new vulnerability or a vanished download, turns red.

The same bytes, proven

A passing build publishes the SHA-256 of every binary in bin/ as a commit status. unit refuses to deploy a binary that doesn't match it.

A pipeline is a task

A repo opts in by having a ci task. Ordering and parallelism are mise's depends; there is no pipeline language on top:

[tools]
go = "1.26"

[tasks.ci]
depends = ["lint", "test"]
run = "go build -o bin/myapp ."

[tasks.lint]
run = "go vet ./..."

[tasks.test]
run = "go test ./..."

Push, and within seconds the commit has a pending check, then a green or red one linked to the build log. Prefer Make? run = "make ci". If it runs in mise, it runs in Punchcard.

Use hosted CI if

Strangers send pull requests. Punchcard is not a sandbox: anyone with write access runs code on the machine. Pull requests from people without it are ignored.

You need many builds at once. One build runs at a time, which keeps workspaces safe and the code simple.

You need a platform. There are no agents, runners, plugins or marketplace, and there won't be.

How a build runs

  1. GitHub sends a webhook for a push to the default branch or a pull request opened or updated, and Punchcard checks its signature.
  2. It brings the repo's workspace to the exact commit: git fetch, git reset --hard, git clean. Ignored files such as caches survive.
  3. No ci task means it stops there, silently.
  4. It posts a pending check, runs mise install and mise run ci, and posts the result linked to the log.

A newer push replaces a build still waiting in the queue, so only the newest commit is built. Watch it all live with punchcard tui, and see how long builds waited and ran with punchcard history.
